- 대안: Laravel (데이터 파이프라인과 언어 통일·작업 범위 확장 목적에 불리해 기각)

- 대안: Nuxt·Astro (참고 자산이 적고 스토리·관리자 화면을 한 앱으로 묶기 불리해 기각)

- 대안: PostgreSQL·전용 DB (컨테이너 추가로 서버 RAM 사용이 늘어 기각)

## D-04 첫 스토리 원소 발견사 (2026-10-08)
- 결정: 첫 스토리 주제는 원소 발견사로 한다.

- 대안: 노벨상·우주 탐사 (출처 명확성·데이터 범위 고정·시그니처 장면 구체성에서 불리해 기각)

## D-05 스토리 구성 파일 JSON (2026-10-08)
- 결정: 스토리 구성(장면·단계·데이터 참조)은 JSON 파일로 정의한다.
- 근거: JSON Schema로 검증하기 쉽고, 관리자 화면(폼)을 스키마에서 생성하기 쉽다.
- 대안: YAML·MDX (스키마 검증·관리자 화면 생성이 번거로워 기각)

## D-06 관리자 인증: 단일 계정 + 세션 쿠키 + 로그인 rate limit (2026-10-08)
- 결정: 관리자는 단일 계정(.env의 비밀번호 해시)으로 인증하고, 세션 쿠키와 로그인 rate limit을 적용한다.
- 근거: 1인 운영이라 다중 사용자·권한 관리가 필요 없고, 시크릿은 .env로만 관리한다.
- 대안: 대안 검토 없음

## D-07 프론트 adapter-static, 스토리 데이터는 발행 시 정적 JSON (2026-10-08)
- 결정: 프론트는 adapter-static으로 빌드(스토리 페이지 프리렌더, /admin은 SPA fallback)하고, 스토리 데이터는 발행 시 정적 JSON으로 생성한다.
- 근거: 운영에 Node 프로세스가 필요 없어 RAM과 관리 대상이 줄고, 공개 페이지는 정적 파일로 서빙된다.
- 대안: Node SSR (운영 프로세스·RAM이 늘어 기각)

## D-08 운영 네트워크: infra_net(DB) + gateway_net(프록시)만 사용 (2026-10-08)
- 결정: 운영 컨테이너는 공유 네트워크 infra_net(DB 접근)과 gateway_net(gateway nginx 프록시)만 사용한다.
- 근거: 공유 인프라 재사용 구조를 따르고, 프로젝트 전용 네트워크·포트 노출을 늘리지 않는다.
- 대안: 대안 검토 없음

- 근거: 두 잡을 main 보호 규칙의 필수 체크로 지정하기 위해 항상 결과가 남아야 한다.
- 대안: 경로 필터로 변경 영역만 실행 (변경 없는 쪽 필수 체크가 대기 상태로 남아 기각)

- 결정: 운영은 web(nginx: 정적 파일·/data 서빙·/api 프록시)과 api(FastAPI) 2개 컨테이너로 구성하고, gateway는 web만 바라본다. 공유 네트워크 충돌을 피하려고 별칭·컨테이너 이름은 plotline-web · plotline-api로 고정한다.
- 근거: gateway 블록이 upstream 1개로 단순해지고, 경로 라우팅이 저장소 안 설정으로 관리된다. nginx 추가 메모리는 수 MB 수준.
- 대안: gateway가 정적·/api를 각각 라우팅 (gateway 설정이 프로젝트 경로 구조에 묶여 기각)

## D-14 발행 데이터: 런타임 볼륨 (2026-10-08)

- 대안: 발행 결과를 저장소에 커밋해 이미지에 포함 (데이터 수정마다 PR·배포가 필요해 기각)

## D-15 배포: 방식 A + 배포 잡 활성화 변수 (2026-10-08)
- 결정: main push 시 변경된 서비스 이미지만 GHCR에 빌드·push하고, 서버 배포는 SSH로 scripts/deploy.sh를 호출한다. 배포 잡은 저장소 변수 DEPLOY_ENABLED가 true일 때만 실행한다.
- 근거: 기존 서버의 방식 A를 재사용하고, 서버 준비(키·디렉터리·.env·gateway) 전에 머지해도 배포 실패가 나지 않게 한다. 서버 명령을 저장소 스크립트로 두어 워크플로를 얇게 유지한다.
- 대안: 서버 준비 후 워크플로를 별도 PR로 추가 (연관 변경이 PR 2개로 나뉘어 기각)

## D-18 출처 규칙(기획서 §4-2 "출처 필수" 수정): 행마다 출처 유형(external/self) 필수. external은 URL·기준 날짜 필수, self는 불필요하며 화면에 "직접 작성" 표시. Claude 데이터화 경로는 external만 허용 (2026-10-08)
- 근거: 직접 작성 콘텐츠 등록을 허용하면서, 출처 없는 AI 조사값이 사실처럼 발행되는 경로는 차단
- 대안: 출처 완전 선택 — 누락과 의도적 무출처 구분 불가로 기각 · 유형 선택만(Claude 경로 제한 없음) — AI 오류 차단 장치 상실로 기각

## D-19 운영 마이그레이션 적용: 배포 시 자동 실행. deploy.sh가 새 api 기동 전에 alembic upgrade head를 1회 실행하고, 실패하면 배포를 중단해 기존 컨테이너를 유지한다. 한 번의 배포에는 추가형 변경만 넣는다 (2026-10-08)

- 대안: 수동 실행 — 누락 시 500 위험으로 기각 · 컨테이너 시작 시 자동 실행 — 재시작마다 실행되고 실패 시 api 기동 불가로 장애 범위가 커 기각

## D-20 관리자 인증: 단일 관리자, .env 계정(argon2id 해시) + 서명된 세션 쿠키(HttpOnly·Secure·SameSite=Strict·8시간), 상태 변경 요청 Origin 검사, 설정 누락 시 로그인 비활성(fail closed) (2026-10-08)
- 근거: 관리자 1명에 필요한 최소 구성. 쿠키는 스크립트에서 읽을 수 없고, 인증 경계가 앱 안에 있어 테스트로 검증 가능
- 대안: JWT 브라우저 저장 — XSS 노출로 기각 · nginx Basic 인증 — 로그아웃 없음·앱 내 경계 없음으로 기각 · GitHub OAuth — 구성 요소 과다로 기각

## D-21 프록시 헤더 신뢰 제거: uvicorn --proxy-headers · --forwarded-allow-ips="*" 제거 (2026-10-08)
- 근거: 앱이 클라이언트 IP·스킴을 쓰지 않으며, 모든 출처를 신뢰하는 설정은 헤더 위조 여지만 남김
- 대안: 신뢰 대역을 web 컨테이너로 축소 — 쓰지 않는 기능을 위한 설정 유지라 기각

## D-22 관리자 인증 보강(외부 검토 1R 반영): 동시 검증 초과 시 429(대기 없음) · 비밀번호 해시 지문을 서명 salt에 포함해 비밀번호 교체 시 세션 무효 · 허용 Origin 형식·해시 비용 범위 검사로 설정 오류 시 비활성 · --no-proxy-headers 명시 · 끝 슬래시 리다이렉트 끔 · 관리자 응답 no-store (2026-10-08)
- 근거: 검증 대기로 인한 스레드풀 고갈 차단, 비밀번호 유출 대응 시 세션 잔존 방지, 운영 설정 실수를 fail closed로 드러냄
- 대안: 세마포어 대기 유지 + gateway 제한에만 의존 — gateway 반영 전 노출 구간이 있어 기각 · 비밀번호 교체 시 SESSION_SECRET 동시 교체를 절차로만 강제 — 실수 여지가 남아 기각
- 외부 검토: A / Fable 1R / 지적 10건 중 수용 9 · 부분 1

## D-23 관리자 인증 보강(외부 검토 2R 반영): 설정 오류 로그는 기동 시 1회 · 검증 오류(422) 응답에서 입력값 제거와 no-store · 구조 테스트에 /api 동적 경로 금지·WebSocket 존재 금지·실제 라우팅 역검증 추가 (2026-10-08)
- 근거: 요청을 이용한 로그 증폭 차단, 비밀번호가 오류 응답으로 되돌아가는 것 방지, 구조 테스트가 놓치는 매칭 경로 보완
- 대안: WebSocket 경로까지 순회하는 검사 — 현재 WebSocket을 쓰지 않아 존재 금지로 대체
- 외부 검토: A / ChatGPT 2R / 지적 4건 중 수용 3 · 부분 1 (외부 검토 종료)
